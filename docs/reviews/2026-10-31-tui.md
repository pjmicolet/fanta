# TUI review #1: 2026-10-31

**Scope:** `1bb2757^..8974fac` on `main`. That covers code mode and spec milestones 1 (layout), 2 (F-keys and help) and 3 (session model).

**Baseline:** the 2026-10-31 usability review (spec §9) and `docs/tui_friction.md`.

**Method:** `fanta-tui-reviewer` drove the TUI headlessly at 80×24, 120×40 and 200×60 through the seven standard workflows. The coordinator re-checked the high-impact claims against the screenshots (`tui-screens/2026-10-31/`) and the code.

## 1. Summary

The redesign holds up. Panes no longer overlap, F-keys execute, and STALE and halt are easy to read. Three things are weak:

- **80×24 is cramped.** The status line drops messages and the flags are cut off.
- **A moved `.asm` is confusing.** Once code has moved and the session is STALE, the gutter shows the edited text's addresses rather than memory's.
- **Some keys are dead or duplicated.** There are also three separate STALE indicators for one fact.

**Top 3 actions:**
1. Build an 80×24 short status form and short pane titles, and get the flags to fit.
2. While code has moved, dim the ASM gutter and hide `>` (Q3).
3. Decide the removal candidates (§5) and the five design questions (§6).

## 2. Friction status

- The Memory tab doesn't follow anything.
- The "Loaded …" message never expires: it is still up after 14 steps (`w2_step14_120x40`).

**New entries** (15, added to the log):
- The STALE gutter in `.asm` shows the wrong addresses (`w4_moved_120x40`).

- `serial_hello.asm` still mentions the `o` key.

## 4. Fit with the system

No interface from spec §5 landed in this range. On the VM side, only the NOP fix landed (`662f0fd`, `f967603`), and the TUI already uses it.

These TUI workarounds point at fixes that belong in other components:

| Workaround in the TUI | Real fix | Owner |
| :--- | :--- | :--- |
| `:eject` treats any opcode-0 word as HALT | The compiler should emit `Halt::emit()` (`0`), not `0x03FFFFFF` | compiler |
| 2 s compile thread | Parser hang B6 | compiler |
| `isBlankOrComment`; line = word | Assembler listing (§5) | vm |
| `kStackTop` copied from `CPU()` | The VM exports the initial SP | vm |
| `:eject` refuses every compiled program | B16: `SP` as a source register | vm |

**Note for the owner:** `tui/disasm.hpp` holds the ISA decode, and `fanta-diff` and `fanta-trace` also depend on it. It is ISA knowledge living outside `common/`.

**Fit test (§0) on this range:**
- The milestone commits cite spec milestones rather than answering the five questions one by one.
- **`ede5971`** added `[ ]` with no spec entry. It fails Q2 and Q3.
- **`9522df5`** added three STALE indicators and `:e!` without updating §4.2. It fails Q3 and the "update the spec in the same commit" rule. §4.2 is now fixed.
- **`dda9c0f`** passes: it removed `s`, `c`, `r` and `o`.

Going forward, each TUI PR's fit-test section answers the five questions one by one.

## 5. Removal candidates (for the owner)

1. **The "Edited: STALE until F9" message.** The status badge and the pane title already say it.
2. **ZOOM mode.** Fold `+`/`-` and panning into the VRAM output overlay, which removes a mode. Also, `i` pans up in ZOOM, which is left over from before.
3. **F9 in BINARY.** It duplicates F6. Say "nothing to build" and drop it from the BINARY hint bar.
4. **The BINARY editor buffer.** It's filled with a disassembly that nothing draws, and `j`/`k` move an invisible cursor.
5. **The IPS bookkeeping in `run()`.** It's dead since IPS was dropped.
6. **The `:compile` alias.** `:build` and `:c` are enough.
7. **`--dump`.** `--screen` supersedes it for UI checks. Cut it, or reduce it to machine state only. `CLAUDE.md` §3 references it.
8. **The `[ ]` keys.** They're the only keys that act on an unfocused tab. `:mem ADDR` would fit better until Tab focus exists.

## 6. Design questions (for the owner)

1. **Should INSERT and `:` pause a running program?**
   - (a) Pause, as today.
   - (b) Keep running, and stop following PC while in INSERT.
   - (c) Keep running in ASM only.

   **Reviewer recommends (b).** Live patching exists for running code.
2. **What happens to ZOOM?**
   - (a) Keep it as a mode.
   - (b) Fold it into the VRAM overlay.

   **Reviewer recommends (b).**
3. **What should the gutter show while an ASM session is STALE because code moved?**
   - (a) Text addresses, as today, which are wrong for memory.
   - (b) The last-built addresses, with `+`/`-` marks.
   - (c) Dim the gutter and hide `>` until F9.

   **Reviewer recommends (c) now and (b) once the assembler listing lands.**
4. **What should the derived pane in a SOURCE session be called?**
   - (a) "ASM build #n", as today.
   - (b) "COMPILED build #n".
   - (c) "DISASM build #n".

   **Reviewer recommends (b).** "ASM" currently names both an editable session kind and a read-only view.
5. **Which tab should the output panel open on?**
   - (a) Serial, always.
   - (b) The last device the program wrote to.

   **Reviewer recommends (b).**

## 8. Decisions (same day)

**Design questions, answered by the owner:**

| Q | Decision |
| :--- | :--- |
| 1. INSERT and `:` pause a running program? | **Yes, pause**: editing shouldn't burn cycles. The spec is corrected. `z` no longer pauses. |
| 2. ZOOM | **Fold** it into the VRAM overlay. `z` opens it; `+`/`-` zoom, `hjkl` pan, `z`/ESC close. |
| 3. Gutter while ASM code has moved | **Dim** the gutter and hide `>` until F9 |
| 4. Derived pane name | **COMPILED** build #n |
| 5. Starting output tab | **The device last written to** (Serial or VRAM), until the user picks a tab |

**Removal candidates.** The owner left these to the coordinator.

| Candidate | Decision | Why |
| :--- | :--- | :--- |
| "Edited: STALE until F9" message | **Removed** | The badge and the pane title already say it |
| ZOOM mode | **Removed** | Folded into the overlay (Q2) |
| F9 in BINARY | **Removed** | It now says "nothing to build", and the hint bar no longer offers it |
| BINARY editor buffer | **Removed** | Nothing drew it |
| IPS bookkeeping | **Removed** | Dead code |
| `[ ]` keys | **Replaced** by `:mem ADDR` | They were the only keys acting on an unfocused tab |
| `:compile` alias | **Kept** | It costs one string compare, and it was the documented command until milestone 2, so old habits keep working |
| `--dump` | **Kept** | Tests use it for machine state that the screen doesn't show (full editor text, all serial output); it isn't a UI path |

All review findings are fixed in `tui/review1-fixes`, except the three friction entries that need the compiler (source-line marker, B6 diagnostics, `return qd;`).
